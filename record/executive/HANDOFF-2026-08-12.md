   anything about publication.

The general lesson, which is worth more than either fix: **applying control 2 to a gate that had
never failed is what broke publication.** A check never observed to fail may be holding an
assumption only one machine satisfies.

## Operational gotchas that cost real time

* **`GITHUB_TOKEN` must be set in the SAME bash call.** Shell state does not carry between tool
  invocations. `source /home/reed/environment-secrets-agi-agents.sh` then
  `export GITHUB_TOKEN=$GH_TOKEN_OAGF`, then the command. `deploy_obligations.observe` and its
  `_api` both read `os.environ.get("GITHUB_TOKEN")` — grep them. They briefly also accepted
  `GH_TOKEN_OAGF`, which meant a test that removed `GITHUB_TOKEN` to exercise the no-token path
  had not actually removed the credential, and the waiter polled for nine minutes.
* **No backticks in commit messages fed through a heredoc.** They trigger command substitution.
* **Bash calls are killed at 10 minutes.** `land.py` now waits 540s for the deploy, under that
  ceiling, and what it no longer covers is recovered by the obligation ledger rather than lost.
  Landing still takes several minutes of gates — run it with `run_in_background: true`.
* **Never pipe `land.py` into `tail`.** A pipeline's exit status is the LAST command's, so
  `land.py ... | tail -6` reports `tail`'s zero however land.py exited. That happened on
  2026-08-12: a background landing reported exit code 0 while `prose-triage` had failed and
  nothing was committed. It was caught only by checking `git log` afterwards. This is the
  repository's own catalogued defect — a status read from the wrong command — committed inside
  the session that spent the day on that defect class. Read `git rev-parse HEAD` and
  `origin/main`, always.
* **`land.py` is the only sanctioned way to land.** Eight gates.

## Five things a fresh session will be tempted to get wrong

1. **There is no Codex floor in code, standing** — the custodian holds rate limiting for that
   channel directly by monitoring weekly usage (2026-08-12, superseding the 2026-08-11 removal
   that carried a seven-day window). Do not "restore" it as if it had lapsed: it was removed
   deliberately, twice. `codex_call.RATE_LIMITING_HELD_BY` is the one string that hands it back
   to the tool. **This record holds no artifact of the monitoring** — no reading, no cadence, no
   threshold — so nothing here can distinguish a watched channel from an unwatched one. That is
   stated in `spend-policy.json` and tested, because "held by the custodian" would otherwise read
   as enforcement a reader could check.
2. **195 unique cloners against 2 unique human visitors.** Never report clone counts as interest.
3. **Do not skip the Codex design review.** Across 2026-08-12 it rejected a design outright, then
   found blocking defects in four consecutive implementations — every one reproduced, every one
   past a full set of green gates and passing suites. Green gates were real and insufficient,
   five times. The rule is in `CLAUDE.md`; the evidence is D-58, D-59 and D-60.
4. **The control-application table reads 0 of 36 and that is the correct reading.** An earlier
   draft ticked fourteen rows; review against the registered control TEXT rather than against
   what had been built left none standing. The recurring error was classifying a missing
   machine-testable requirement as "not closable in code". A `residue` is for what no code could
   supply; unbuilt work is a `gap`.
5. **Never pipe `land.py` into anything.** Its exit status is the pipeline's last command. A
   background landing reported exit 0 while a gate had failed and nothing was committed — caught
   only by reading `git rev-parse`. This is already in the gotchas above; it is repeated here
   because it happened during the session whose subject was that defect class.
