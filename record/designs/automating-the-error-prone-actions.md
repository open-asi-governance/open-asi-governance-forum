# Automating the error-prone routine actions — plan

**Ranked by recorded failures, not by intuition.** Every item below names the instances that
justify it. An automation with no failure behind it is not on this list, because the layer's
judgment about which of its own actions are risky is exactly the judgment that has been wrong.

The selection rule: automate an action when **the error is silent** — when the wrong result looks
identical to the right one. Loud errors (a traceback, a refused push) do not need a tool; they
need nothing. Every failure below produced a plausible, confident, wrong answer.

---

## 1. Deriving a headline count from the corpus — **the worst, and the least suspected**

**Instances (all 2026-08-10, both self-favouring):**

| Claim | Truth | Mechanism |
|---|---|---|
| "4 caught failures" for the completion gate | 1 real, 3 synthetic | read `problems`, not the `note` beside it saying `synthetic` |
| "0 `search_web` invocations corpus-wide" | 9 receipts | scanned `o["samples"]`; **69 raw files use `responses`/`failures`** and returned zero silently |
| "117 fetch receipts" | 223 | same blind spot |

The second is the shape that matters: **an unrecognised schema returned zero rather than
failing.** A count that cannot see a file reports absence, and absence is indistinguishable from
a true zero in the output. Both errors ran toward a cleaner story for this layer, and the second
was caught only because an external reviewer read a raw file.

**Automate:** `tools/derive_counts.py`. Walks every raw file, and **refuses** — non-zero, no
number printed — if any file's disposition containers are unrecognised. Reports the denominator
(files visited, files parsed, samples/responses/failures seen) alongside every count, and counts
across *all* dispositions including `failures` and `rejected`, because the record's own invariant
is that nothing solicited is discarded.

**The rule this enforces:** a headline number in any document is generated by this tool or it is
not published. Manual transcription of a count is now a defect class.

## 2. Reading a verdict from output text instead of an exit status

**Instances:** `echo "$(basename $f) rc=$?"` reporting basename's status (two red suites pushed);
`tail -1` of a failing suite; and again on 2026-08-10, `run_all.py | tail -2` printing
`All 16 suites passed` from an inner suite while the runner exited **1**.

The last one is the instructive one: the gate for this exact failure already existed, was
documented in `CLAUDE.md`, and I did it anyway — because `tail` is what you reach for when you
want to see the end of a long output, and the summary line of the *penultimate* suite sits there
looking like a verdict.

**Automate:** fold into item 3 rather than a standalone tool. A separate `run_gate.py` would still
leave the tempting `| tail` available; making the *landing* path the only sanctioned way to
declare work done removes the occasion.

## 3. The commit → push → attest ceremony

Five steps in fixed order, each individually skippable, and skipping one is silent: `rebuild.py`,
the suite, `check_quotations.py`, `check_executive_context.py`, then commit, push, verify the
remote ref, attest both. On 2026-08-10 the quotation checker caught a bad quote **only because
`rebuild.py` happened to be run first** — nothing required it.

Related recorded failures: three commits to a round branch while `git push origin main` reported
success on an unchanged main; a conflicted merge completed blind, leaving conflict markers in
`MANIFEST.sha256` and the anchor log.

**Automate:** `tools/land.py`. Runs every gate, **captures each exit status directly**, refuses on
any failure without touching git, then commits, pushes, re-verifies the commit is reachable from
`origin/main`, and files both attestations. Also checks the lease *before* starting, and refuses
to run on a detached head or a branch other than the intended one.

## 4. Appending tests after the summary and exit

**Instances: two.** Eight tests once sat after `sys.exit(0)` and never ran at all; on 2026-08-10 a
new block landed after the summary `print`, so the file reported `67 passed` and then executed
fifteen more tests whose results were never counted.

Silent by construction: the file prints a green total and exits 0 either way.

**Automate:** a meta-test asserting that no `def test_` or bare `check(` call appears after the
summary line in any test file. Cheap, and it closes a hole that has now opened twice.

## 5. What deliberately stays manual

**The truth of a pinned file.** `check_executive_context.py` passed on `oagf-CLAUDE.md` while it
contained a claim already proven false — the check verifies *identity, not truth*. No tool
distinguishes a faithfully-deployed false sentence from a faithfully-deployed true one. What item
1 does is remove the most common *source* of such sentences; the residue needs a reader.

**Gate modification.** `executive_log.py` cannot attest that its own semantics are unchanged, and
neither can anything else inside this repository. This needs a pin held externally, which does not
exist and is not automatable from here.

**Clause and question selection.** Every instrument this layer builds is chosen by this layer.
Automating the mechanics of a ballot does nothing about which propositions reach it.

---

## Order

1 and 4 first — cheapest, and 1 is a prerequisite for scoring the qualification round honestly.
Then 3, which is the one that changes daily practice. 2 is subsumed by 3.
